# Story 1.1 — Architecture, LangChain project seed, and Open WebUI connection

## Purpose

Agree the classroom architecture, then seed a minimal Python project that answers chat messages from the existing Open WebUI using a LangChain prompt and a Grok model. Later stories build on this seed.

## What this story implements in plain English

- You type a message in Open WebUI and get a reply from Grok.
- The reply comes from a small app running on your own computer, not from Open WebUI itself.
- Replies work both all-at-once and word-by-word.
- The app starts even with no API key, and tells you plainly if the key or model name is missing when you ask a question.
- Open WebUI stays exactly as it is; you only point it at your local app.

## Prerequisites

- Open WebUI already installed and working (supplied; do not reinstall, reconfigure, or modify it).
- Python 3.12 and UV installed.
- From the instructor: the Grok model name and approval of the architecture (step 1 below).
- Your own Grok API key, to be placed only in untracked `.env`.
- No `docs/config.yaml`, `docs/architecture.md`, or other stories exist yet; project path = repository root.

## Work to do

### 1. Architecture (do this first, then stop for approval)

Create `docs/architecture.md` (or update if present) recording:

- Single flow: `Open WebUI → this local application's OpenAI-compatible chat endpoint → LangChain prompt and Grok model → answer in Open WebUI`.
- Open WebUI is already installed and working; it is the supplied chat client only. Participants must not reinstall, reconfigure, modify, or build it.
- The capstone is a small **Learning Companion Chatbot**: no custom frontend, no second demo application.
- Boundaries: API keys only in untracked `.env`; application instructions kept separate from user messages.
- Out of scope: authentication, authorization, security hardening, databases, persistent memory, RAG, production deployment, extensive tests.

### 2. Project seed (after approval only)

Create or change:

- `pyproject.toml` — Python 3.12, UV; dependencies: `fastapi`, `pydantic-settings`, `langchain`, the Grok-compatible LangChain provider package (`langchain-xai`), `uvicorn`; dev: `ruff`, `pytest`.
- `uv.lock` (generated by UV).
- `.env.example` with exactly:
  ```
  APP_ENV=development
  GROK_API_KEY=
  GROK_API_BASE_URL=https://api.x.ai/v1
  GROK_MODEL_NAME=
  HOST=127.0.0.1
  PORT=8000
  ```
  Document in README that the instructor supplies the model name and participants put their real key only in untracked `.env`. No Claude, alternate-provider, database, or production settings.
- `.gitignore` — ensure `.env`, `.venv/`, caches are ignored (keep existing entries).
- `README.md` — short: setup, run command, Open WebUI connection value.
- `src/learning_companion/__init__.py`
- `src/learning_companion/config.py` — Pydantic settings reading the six names above.
- `src/learning_companion/chain.py` — one LangChain flow: prompt (fixed Learning Companion system instruction + latest user message) → Grok chat model → string output. Model is built lazily; if key or model name is blank, raise a clear configuration error only at call time.
- `src/learning_companion/main.py` — FastAPI app:
  - `GET /health`
  - `GET /v1/models` — lists the configured Grok model name.
  - `POST /v1/chat/completions` — accepts `model`, `messages` (text; roles `system`/`user`/`assistant`), `stream`. `stream=false`: normal OpenAI-compatible JSON. `stream=true`: text-only OpenAI-compatible SSE chunks, then a stop chunk, then `[DONE]`. Same chain serves both. Configuration error returns an honest OpenAI-style error message.
- `tests/` — directory with one minimal smoke test (`/health`) only.

Do not add: custom Open WebUI events, a second chat route, a custom UI, tool calls, LangGraph, agents, MCP, advanced streaming, or a broad test suite. Keep it small; only the latest user message is used.

### 3. Open WebUI connection

If the existing connection needs it, set only the application-side values: base URL `http://127.0.0.1:8000/v1` and select the configured model. Do not alter Open WebUI itself.

## Completion checks

Run only these lightweight checks:

```

```

- Without a key, the app starts and a chat request returns a configuration error.
